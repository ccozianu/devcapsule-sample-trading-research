# License Repository Work Under Apache License 2.0

## Context

The repository was publicly visible, but public visibility alone did not grant
redistribution or modification rights. Its package metadata described the
project as proprietary, GitHub detected no license, and the repository did not
contain a license file. Distribution and contribution terms therefore needed an
explicit owner decision before the project begins incorporating its first
redistributable evaluation fixture set.

## Options Considered

1. Keep the repository proprietary, retaining maximum control but preventing
   ordinary open-source use and contribution.
2. Adopt Apache License 2.0, permitting broad use and modification while
   providing explicit patent terms and preserving notices.

## Decision

License repository-authored code and documentation under Apache License 2.0.
Repository-authored fixtures receive the same license unless marked otherwise.
Imported or adapted fixtures retain their applicable source licenses and require
independent provenance and redistribution review.

## Rationale

The project owner selected Apache License 2.0. Its permissive terms support an
open research implementation, and its express patent grant gives contributors
and downstream users clearer terms than leaving the project proprietary or
unlicensed.

## Consequences

- The canonical Apache License 2.0 text is stored in `LICENSE`.
- Package metadata and developer documentation identify Apache-2.0.
- Fixture source and license metadata remain mandatory; the repository license
  does not relicense third-party material.
